## State-machine and safety contract

- Inputs: raw button logic, optional cancellation logic, sample period (ms), debounce request (ms),
  and maximum-on request (ms).
- States: `IDLE`, `QUALIFY_PRESS`, `ACTIVE`, `QUALIFY_RELEASE`, and `LOCKOUT`.
- Output: simulated GPIO logic is high only in `ACTIVE` and `QUALIFY_RELEASE`.
- Debounce: `N_d = max(1, ceil(debounce_ms / sample_period_ms))`, so qualification never
  completes earlier than requested.
- Maximum-on: the request must be at least one sample period and
  `N_t = floor(max_on_ms / sample_period_ms)`, so modeled high time never exceeds the request.
- Cancellation: same-sample transition to safe-low `LOCKOUT`.
- Recovery: held-high input cannot retrigger; `N_d` consecutive low samples re-arm `IDLE`, after
  which a later qualified press can drive again.
- Resources: input length and derived timing counts are capped at 1,000,000 samples; size is checked
  before signal-value scanning and all derived time/count values must remain finite.

## Figure, control, metric, and unit inventory

Figures in `experiment.m`:

1. **P02 baseline transitions** — raw/cancel logic, state code, and simulated GPIO versus time (ms).
2. **P02 baseline metrics** — accepted presses, GPIO rises, timeouts, and cancels (event counts),
   with maximum high run in ms.
3. **P02 debounce sweep** — GPIO rising-edge count and first-high time (ms) versus requested
   debounce time (ms).
4. **P02 maximum-on sweep** — observed longest high run (ms) and timeout-event count versus
   requested maximum-on time (ms).
5. **P02 broken debounce assumption** — raw/GPIO logic versus time (ms) and qualified versus
   bypassed GPIO rising-edge counts.

Controls in `interactive.m`:

- debounce spinner: 0–15 ms, default 5 ms;
- maximum-on spinner: 5–100 ms, default 80 ms;
- deterministic contact-bounce spinner: 0–12 ms, default 6 ms;
- scenario dropdown: normal press, stuck high, or cancel and recovery.

Model outputs and metrics:

- time, sample period, requested/quantized debounce, requested/quantized maximum-on, GPIO high time,
  and maximum high-run duration: milliseconds;
- debounce/timeout counts, high-run samples, accepted presses/releases, timeouts, cancels, and GPIO
  rising/falling edges: samples or event counts as named;
- raw button, cancel, and GPIO: simulated binary logic;
- state code: dimensionless integer 0–4 with retained state-name mapping.
